Setting Up Vitest + React Testing Library

Build the smallest reliable test environment: Vitest runs tests, jsdom supplies browser-like DOM APIs, and React Testing Library renders components through their public output.

Estimated time: 45–60 minutes · Milestone: CountryCard smoke test

1. Learning Objectives

  • Explain the responsibilities of Vitest, jsdom, and React Testing Library
  • Configure jsdom and a shared setup file
  • Add repeatable test scripts
  • Write a CountryCard smoke test
  • Diagnose setup failures by architectural layer

2. Pre-Coding Quiz

Need 4/5 to proceed.

Question 1 of 5

Vitest reports document is not defined while rendering CountryCard. What is the first configuration to inspect?

Rendering needs DOM globals; jsdom supplies them in the test process.
Question 2 of 5

Which package is responsible for render() in these component tests?

React Testing Library exports render; jest-dom adds matchers, user-event simulates interaction, and jsdom supplies the environment.
Question 3 of 5

Why put @testing-library/jest-dom/vitest in a setup file?

Setup files centralize shared initialization such as DOM matchers.
Question 4 of 5

What does a smoke test establish?

A smoke test is deliberately narrow: basic rendering works without throwing.
Question 5 of 5

Which command is best for one deterministic verification run?

The run command executes once and exits with success or failure, making it suitable for checks and CI.

3. The Concept — Three Tools, Three Jobs

npm install -D vitest jsdom @testing-library/react \
  @testing-library/jest-dom @testing-library/user-event

Vitest runs tests; jsdom supplies DOM globals; Testing Library renders and queries. Keep these responsibilities separate when diagnosing failures.

4. Lab

Lab objective: configure Vitest and render CountryCard in the first smoke test.
1

Install test dev dependencies using the command above.

2

Add test configuration

import { defineConfig } from 'vitest/config';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  test: {
    environment: 'jsdom',
    setupFiles: './test/setup.js'
  }
});
3

Create shared setup

import '@testing-library/jest-dom/vitest';
import { cleanup } from '@testing-library/react';
import { afterEach } from 'vitest';

afterEach(cleanup);
4

Add scripts

"test": "vitest run",
"test:watch": "vitest"
5

Write the smoke test

import { test } from 'vitest';
import { render } from '@testing-library/react';
import CountryCard from './CountryCard';

test('renders CountryCard without crashing', () => {
  render(<CountryCard name="Japan" region="Asia" />);
});

Run npm test. No output assertion yet; Session 29 adds meaningful queries.

7. Code Review Checklist

8. Post-Coding Quiz

Question 1 of 5

The smoke test fails before CountryCard executes because JSX cannot be transformed. Which layer is suspect?

A transform failure occurs before component behavior and points to build/test configuration.
Question 2 of 5

Why explicitly call cleanup after each test when not relying on globals?

Cleanup isolates tests by unmounting rendered trees and clearing their containers.
Question 3 of 5

Which failure is the smoke test designed to catch?

The smoke test only establishes successful rendering; later sessions protect output and interaction.
Question 4 of 5

A matcher says toBeInTheDocument is not a function. What is most likely missing?

toBeInTheDocument is supplied by jest-dom, not core Vitest.
Question 5 of 5

Why keep user-event installed even though the smoke test does not use it yet?

The testing sequence installs the interaction tool now and introduces its behavior later.

9. Reflection Questions

  1. Which tool owns each step from test discovery to DOM query?
  2. What does the smoke test not prove?
  3. How would you diagnose a missing document differently from a render exception?

10. What Breaks If Setup Is Removed?

  • Without jsdom, DOM rendering has no document.
  • Without setup, custom DOM matchers and explicit cleanup disappear.
  • Without scripts, test execution becomes inconsistent.

11. What Engineering Concept Was Learned Today

A component test needs a runner, a DOM environment, and a rendering/query library—each with a distinct responsibility.
