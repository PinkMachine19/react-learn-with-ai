2. Pre-Coding Quiz

Need 4/5 to proceed. Every option describes a believable coding decision, so use the reason—not answer length—to choose.

Question 1 of 5

Which path best describes how remote country data reaches the screen?

The service retrieves and converts outside data, App holds the screen state, CountryList repeats cards, and CountryCard presents one item.
Question 2 of 5

Why does CountryList own favorites in the current application?

CountryList is the lowest shared parent that can serve every card. Moving favorites to App would place the state higher than its actual users require.
Question 3 of 5

Which test belongs closest to countryServices.js?

Malformed-response handling is a service concern. The other options describe component or hook behavior.
Question 4 of 5

What does npm run build check that a browser walkthrough may miss?

The production build catches packaging, import, and asset problems. It does not guarantee server uptime or complete behavioral coverage.
Question 5 of 5

What makes a capstone explanation convincing?

Real understanding connects behavior to concrete files and reasons. Vocabulary without the working story does not demonstrate mastery.

What problem does this solve? No single file delivers the whole product.

Why should I care? Contracts explain what each boundary receives and returns.

What would happen if React did not have this? Without them, failures travel unpredictably across layers.

8. Post-Coding Quiz

Question 1 of 5

Search works, but clearing it does not restore all countries. Which route should you trace?

Follow the actual user action through its callback, state change, recalculation, and rendered list. That route isolates where the behavior stopped.
Question 2 of 5

The API changes name.common to displayName. Which file should absorb most of that change?

The service translates provider fields into the app’s familiar Country shape. Keeping that translation there protects presentation components.
Question 3 of 5

Which capstone evidence best protects the favorite feature?

The favorite promise is interactive and visible. A click-and-observe test proves the state route works rather than merely documenting its intention.
Question 4 of 5

Tests pass, but npm run build fails on an import path. Is the capstone ready to deploy?

Tests and builds check different risks. A failed production build is a real deployment blocker even when behavior tests pass.
Question 5 of 5

Which next-step note is most useful?

A useful next step names the exact risk, location, and evidence needed. Vague cleanup language gives the next developer no actionable starting point.

9. Reflection Questions

  1. What problem did this lesson solve?

    The capstone is complete when behavior works, boundaries can be explained, and evidence supports the important decisions.

  2. Why should a professional care?

    The boundary makes failures easier to locate and future changes easier to verify without rereading the entire application.

  3. What cost or tradeoff remains?

    Every new boundary, state, or document adds something developers must learn. Keep it only while it makes the behavior clearer than the simpler alternative.

10. What Breaks If This Boundary Is Ignored?

  • The failure appears far from the responsibility that caused it.
  • Unrelated code changes together because ownership is unclear.
  • The page can look correct while another file receives the wrong input or result.
  • The next learner inherits a rule without understanding its reason.
