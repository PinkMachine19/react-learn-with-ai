Reusable Components

Design small UI primitives whose prop contracts express stable variation without leaking feature-specific decisions.

Estimated time: 50–65 minutes · Milestone: Replace and verify

const variants = ['label text', 'click handler', 'country filtering rule', 'disabled state'];

// One defensible solution
function reusableButtonInputs(variants) {
  const stable = new Set(['label text', 'click handler', 'disabled state']);
  return variants.filter(item => stable.has(item));
}
This solution keeps feature filtering outside the generic Button contract.

9. Reflection Questions

  1. What is the strongest signal for extraction?

    Repeated semantics and behavior with a stable variation point—not visual resemblance alone.

  2. Why keep filtering out of Button?

    Filtering belongs to the feature; putting it in Button makes a generic primitive depend on domain policy.

  3. What does children enable?

    Composition: callers provide content while the component retains ownership of structure and semantics.

10. What Breaks If This Boundary Is Ignored?

  • Responsibilities drift across unrelated modules.
  • Safe changes become harder to verify and explain.
  • Future learners inherit coupling without its original reasoning.

11. What Engineering Concept Was Learned Today

A reusable component is a small, stable UI contract—not a dumping ground for every variation.
