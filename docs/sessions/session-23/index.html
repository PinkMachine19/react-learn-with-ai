Why Mock Data Matters

Build a realistic data contract before a backend exists, so the interface can keep moving without waiting for an API.

Estimated time: 35–40 minutes

1. Learning Objectives

  • Explain how mocks remove frontend dependency on an unfinished backend
  • Describe a data contract as agreed field names and types
  • Create valid JSON containing ten consistently shaped countries
  • Distinguish production data from representative development data

3. The Concept — Build Against a Contract

Mock data is a temporary source, not disposable thinking

A mock replaces where data comes from, but should preserve what the UI expects. If a country card needs id, name, region, and population, every mock country should provide those fields with consistent types.

{
  "id": 1,
  "name": "Canada",
  "region": "Americas",
  "population": 40000000
}

Why use JSON?

JSON resembles a real HTTP response and cannot contain functions or imports. That constraint keeps the file focused on data. In Session 24, a service will own access to it so components do not care whether records came from a mock or an API.

Watch the syntax: JSON has no comments or trailing commas. Keys and string values must use double quotes.

4. Lab

Lab objective: Create src/mock/countries.json with ten realistic countries sharing one consistent contract.
1

Create the mock folder and file

src/
  mock/
    countries.json
2

Start a JSON array

[
  { "id": 1, "name": "Canada", "region": "Americas", "population": 40000000 },
  { "id": 2, "name": "Japan", "region": "Asia", "population": 124000000 }
]
3

Expand to ten records

Use unique numeric IDs, at least four regions, non-empty names, and numeric populations. Keep the exact same four keys on every object.

4

Validate

node -e "JSON.parse(require('fs').readFileSync('src/mock/countries.json'))"

No output means parsing succeeded. Also count exactly ten objects and inspect the final record for a trailing comma.

10. What Breaks If This Code Is Removed?

  • Remove fields: Consumers cannot rely on a stable country shape.
  • Use inconsistent types: formatting, filtering, and comparisons become unpredictable.
  • Embed records in components: data access and rendering become coupled again.
