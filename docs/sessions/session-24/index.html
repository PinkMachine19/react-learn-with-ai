Building a Service Layer

Components should ask for country data without knowing whether it came from an array, JSON fixture, cache, or HTTP API. Today you create that boundary with small synchronous functions.

Estimated time: 45–55 minutes · Focus: separation of concerns · Promises arrive in Session 25

1. Learning Objectives

  • Define separation of concerns in the context of data access
  • Explain why components should not know storage details
  • Build focused service functions with clear names and return values
  • Return copies when callers should not mutate shared source data
  • Distinguish a missing single item from an empty collection

2. Pre-Coding Quiz

Answer before reading. Need 4/5 to proceed.

Question 1 of 5

What concern belongs in a country service?

A service owns data-access decisions; components own rendering and interaction.
Question 2 of 5

Encapsulation localizes a later move from fixtures to a real API.
Question 3 of 5

A collection query can validly contain zero results, represented by an empty array.
Question 4 of 5

Array.find returns the first matching element or undefined.
Question 5 of 5

3. The Concept — Put Data Access Behind a Boundary

Without a service, storage knowledge leaks

// CountryList.jsx now knows the exact data file
import countries from '../data/countries';

const asia = countries.filter(country => country.region === 'Asia');

If the source later changes to a JSON fixture or HTTP endpoint, every importing component may need edits. The filter rule can also become duplicated across screens.

With a service, callers ask questions

import countries from '../data/countries.js';

export function getCountries() {
  return [...countries];
}

export function getCountryById(id) {
  return countries.find(country => country.id === id);
}

export function getCountriesByRegion(region) {
  return countries.filter(country => country.region === region);
}

The service name describes intent. The implementation can change without teaching components a new storage mechanism.

Do not jump ahead: These functions are deliberately synchronous. Session 25 changes the boundary to fake asynchronous responses. Keeping today synchronous makes the architectural responsibility visible before Promise timing is added.

Be precise about copies and absence

[...countries] protects the source array from push, sort, and splice performed on the returned array. It is only a shallow copy: mutating a country object still affects the same object. A lookup for one item returns an object or undefined; a collection filter always returns an array, possibly empty.

4. Lab

Lab objective: Create src/services/countryService.js with synchronous functions that encapsulate access to country data.
1

Create the correctly named service file

Use singular countryService.js. If an older plural countryServices.js exists, compare its behavior before replacing or renaming it; do not keep two competing service modules.

2

Import the current country source

import countries from '../data/countries.js';

The service owns this source-specific import. Components should import service functions instead.

3

Add three named functions

export function getCountries() {
  return [...countries];
}

export function getCountryById(id) {
  return countries.find(country => country.id === id);
}

export function getCountriesByRegion(region) {
  return countries.filter(country => country.region === region);
}
4

Use the service at the data boundary

import { getCountries } from '../services/countryService.js';

function CountryList() {
  const countries = getCountries();
  // existing empty-state and map JSX stays the same
}

Update only the data acquisition in CountryList.jsx. Rendering remains the component's concern.

5

Verify behavior

Run npm run build. Confirm all cards still render, an unknown id returns undefined, and an unknown region returns []. No delays, async, or await belong in this session.

8. Post-Coding Quiz

Question 1 of 5

If the data source changes later, where should most implementation changes occur?

The stable service API isolates consumers from source changes.
Question 2 of 5

A caller sorts the array from getCountries(). Why does returning a spread copy help?

Spread creates a distinct outer array, protecting source order from array-level mutation.
Question 3 of 5

What should a component know about the service's storage?

Dependency on behavior rather than implementation is the point of the boundary.
Question 4 of 5

Why should filter() not be followed by if (!result) to detect no matches?

Check result.length === 0 if empty results require special handling.
Question 5 of 5

What changes in Session 25?

Fake async responses preserve the service boundary while introducing realistic timing.

9. Reflection Questions

  1. Which details are hidden by the service, and which are part of its public contract?
  2. Why is an empty array a useful result for a collection query?
  3. What mutation does a shallow array copy prevent, and what mutation does it not prevent?

10. What Breaks If This Layer Is Removed?

  • Components become coupled to the current data file.
  • Query rules can be duplicated and drift apart.
  • A later API migration touches presentation code instead of one boundary.
  • Testing data behavior independently becomes harder.

11. What Engineering Concept Was Learned Today

A service layer encapsulates data access behind intention-revealing functions, separating storage decisions from UI rendering.
