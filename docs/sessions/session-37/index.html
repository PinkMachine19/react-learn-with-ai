3. The Concept — Effects Synchronize Outside React

Big picture: Understand why effects exist, when they run, why cleanup matters, and why ordinary calculations should stay out of them.

Rendering should stay pure

What problem does this solve? React may call a component more than once while deciding UI.

Why should I care? Pure rendering produces the same JSX without changing the outside world.

What would happen if React did not have this? Without purity, merely checking UI could start timers or subscriptions.

Effects synchronize external systems

What problem does this solve? Some work must happen because UI became active.

Why should I care? Effects connect committed React state to timers, events, network APIs, or browser features.

What would happen if React did not have this? Without effects, components lack a lifecycle-safe place for synchronization.

Dependencies describe what setup reads

What problem does this solve? An effect can accidentally keep an old value.

Why should I care? Dependencies tell React when the synchronization is outdated.

What would happen if React did not have this? Without correct dependencies, callbacks use stale state or subscriptions never update.

Cleanup undoes setup

What problem does this solve? Timers and listeners can survive after a component no longer needs them.

Why should I care? Cleanup prevents duplicate work and updates from abandoned subscriptions.

What would happen if React did not have this? Without cleanup, remounts accumulate listeners and memory.

9. Reflection Questions

  1. What problem did this lesson solve?

    useEffect synchronizes committed React state with systems outside React; it is not a general-purpose calculation tool.

  2. Why should a professional care?

    The boundary makes failures easier to locate and future changes easier to verify without rereading the entire application.

  3. What cost or tradeoff remains?

    Every new boundary, state, or document adds something developers must learn. Keep it only while it makes the behavior clearer than the simpler alternative.

10. What Breaks If This Boundary Is Ignored?

  • The failure appears far from the responsibility that caused it.
  • Unrelated code changes together because ownership is unclear.
  • The page can look correct while another file receives the wrong input or result.
  • The next learner inherits a rule without understanding its reason.
