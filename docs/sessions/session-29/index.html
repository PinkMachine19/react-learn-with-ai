Layer 5Session 29Testing

Testing Props and Output

Render CountryCard with known props, query the DOM through semantic roles and visible text, and assert the contract a user can observe.

Estimated time: 40–50 minutes · Milestone: verify country name and region output

1. Learning Objectives

  • Render a component with controlled prop values
  • Choose role queries before text or test-id fallbacks
  • Distinguish getBy, queryBy, and their intended failure behavior
  • Use jest-dom assertions for readable DOM expectations
  • Avoid selectors tied to CSS or wrapper structure

2. Pre-Coding Quiz

Need 4/5 to proceed.

Question 1 of 5

Which query best locates the country title “Japan” rendered as an h2?

Role plus accessible name describes the semantic element and its user-visible identity.
Question 2 of 5

You expect “Brazil” not to appear. Which query allows an absence assertion?

queryBy returns null when absent, allowing not.toBeInTheDocument().
Question 3 of 5

Why is a CSS selector usually weaker than getByRole?

CSS and wrapper changes may be harmless to users but still break implementation-coupled selectors.
Question 4 of 5

What does toBeInTheDocument() communicate?

The matcher asserts document membership, producing a clearer DOM-specific message than generic truthiness.
Question 5 of 5

When is getByText appropriate?

Visible text is a good query when role, label, or other accessible semantics do not identify the target.

3. The Concept — Query Like a User

Testing Library’s query priority reflects accessible use. Start with role and accessible name, then use labels, visible text, and only finally test IDs when no user-facing identifier exists.

render(<CountryCard name="Japan" region="Asia" />);

expect(screen.getByRole('heading', { name: 'Japan' }))
  .toBeInTheDocument();
expect(screen.getByText('Region:Asia')).toBeInTheDocument();

4. Lab

Lab objective: Prove CountryCard renders controlled props through accessible DOM output.
End state: Known props produce precise semantic output and absence checks avoid broad false matches.
1

Import APIs

Use screen for document queries and expect for assertions.

import { render, screen } from '@testing-library/react';
import { expect, test } from 'vitest';
import CountryCard from './CountryCard.jsx';
2

Render known props

Choose deterministic inputs.

test('renders supplied country details', () => {
  render(<CountryCard name="Japan" region="Asia" />);
});
3

Assert semantic output

Query the title by role and region by exact text.

render(<CountryCard name="Japan" region="Asia" />);

expect(
  screen.getByRole('heading', { name: 'Japan' })
).toBeInTheDocument();

expect(
  screen.getByText('Region:Asia', { exact: true })
).toBeInTheDocument();
4

Inspect a failure

Misspell once, read the diagnostic, then restore.

// Temporary diagnostic:
expect(
  screen.getByRole('heading', { name: 'Japna' })
).toBeInTheDocument();

// Run npm test, inspect available roles, then restore "Japan".
5

Assert absence precisely

Use queryBy for absence and exact matching.

render(<CountryCard name="Japan" region="Asia" />);

expect(
  screen.queryByText('Ghana', { exact: true })
).not.toBeInTheDocument();

expect(
  screen.queryByText('Eurasia', { exact: true })
).not.toBeInTheDocument();

Question 1 of 5

The h2 becomes an h3 but remains a heading named Japan. What happens to the role query?

Both h2 and h3 have heading role; add a level option only when hierarchy is part of the requirement.

A loose substring pattern can match unintended output; use exact text or a bounded expression when exactness matters.
Question 4 of 5

Controlled inputs produce a clear example mapping from props to observable output.
Question 5 of 5

9. Reflection Questions

  1. Which output deserves a role query and which requires visible text?

    Headings, buttons, links, and other semantic controls deserve role queries with accessible names. Plain descriptive copy without a stronger semantic target may require a visible-text query.

  2. When would heading level be part of the contract?

    Heading level matters when the component must preserve a particular document hierarchy for navigation or accessibility. Otherwise, the heading role and accessible name usually express the useful behavior without overspecifying markup.

  3. What overly broad matcher could hide a bug here?

    A loose substring such as /Asia/ could match unintended text like Eurasia or a hidden duplicate. A scoped, exact, or word-bounded matcher better protects the intended output.

10. What Breaks If Assertions Are Removed?

  • The test returns to proving only that rendering did not throw.
  • Prop wiring regressions can pass silently.
  • Semantic output is no longer protected.

11. What Engineering Concept Was Learned Today

Semantic queries turn component props and visible DOM output into a refactor-resistant behavior contract.
