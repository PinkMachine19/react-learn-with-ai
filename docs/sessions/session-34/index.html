Custom Hooks

Extract reusable stateful logic into a custom hook while keeping rendering decisions in components.

Estimated time: 50–65 minutes · Milestone: Integrate and verify
Optional Warm-Up5-Minute Wake-Up Challenge: Find the Hook Boundary

Give yourself five minutes. Separate stateful search mechanics from the JSX that presents results. Use a scratch file, Node REPL, or browser console; no full React app run is required.

const concerns = ['query state', 'filter calculation', 'result heading', 'input markup', 'clear-query action'];

function hookConcerns(concerns) {
  // Return logic the hook should own.
}
// One defensible solution
function hookConcerns(concerns) {
  const logic = new Set(['query state', 'filter calculation', 'clear-query action']);
  return concerns.filter(item => logic.has(item));
}
The hook owns stateful mechanics; the component keeps headings and input markup.

9. Reflection Questions

  1. What belongs in a custom hook?

    A coherent reusable stateful behavior: its state, derived values, effects, and actions.

  2. Why not store filtered results in state?

    They can be derived from countries and query; duplicate state can become stale.

  3. Why must hook calls stay unconditional?

    React relies on identical call order to associate hook state with each render.

10. What Breaks If This Boundary Is Ignored?

  • Responsibilities drift across unrelated modules.
  • Safe changes become harder to verify and explain.
  • Future learners inherit coupling without its original reasoning.

11. What Engineering Concept Was Learned Today

Custom hooks reuse behavior while components retain control of presentation.
