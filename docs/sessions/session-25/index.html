Fake Async Responses

Preserve the service boundary from Session 24 while changing its timing contract: callers now receive Promises, wait for results, and handle rejection.

Estimated time: 50–60 minutes · Focus: Promise contracts, latency, and failure paths

3. The Concept — Same Data, Different Timing

Session 24 returned arrays and objects immediately. A real API returns a Promise, so callers must wait. We can model that behavior with one helper:

function delay(ms) {
  return new Promise(resolve => setTimeout(resolve, ms));
}

Convert the service operation

export async function fetchAllCountries() {
  await delay(300);
  return [...countries];
}

The async keyword guarantees a Promise return. The delay keeps it pending briefly. The final return fulfills it with a fresh array.

Consume it safely

async function run() {
  try {
    const countries = await fetchAllCountries();
    console.log(countries);
  } catch (error) {
    console.error(error.message);
  }
}
Common mistake: logging fetchAllCountries() without await logs the Promise, not the resolved array.

4. Lab

Lab objective: Convert countryService.js to return delayed Promises and verify the functions with async/await and error handling.
1

Add delay

function delay(ms) {
  return new Promise(resolve => setTimeout(resolve, ms));
}
2

Make all-countries asynchronous

export async function fetchAllCountries() {
  await delay(300);
  return [...countries];
}
3

Add asynchronous queries

export async function fetchCountryById(id) {
  await delay(150);
  const country = countries.find(c => c.id === id);
  if (!country) throw new Error(`Country ${id} not found`);
  return country;
}
export async function fetchCountriesByRegion(region) {
  await delay(200);
  return countries.filter(c => c.region === region);
}

An empty region result is a valid empty array, so do not test it with if (!results); empty arrays are truthy.

4

Verify success and failure

Use an async test function with try/catch. Await all countries, one known ID, one region, and an unknown ID. Confirm the unknown ID reaches catch only after its delay.

5

Verify the pending contract

9. Reflection Questions

  1. What behavior does the delay realistically simulate?

    The delay simulates latency: a pending period before success or failure, including the need to wait and handle completion order. It does not reproduce HTTP, connectivity, server processing, or real network errors.

  2. Why should an unknown ID reject while an unmatched region can return []?

    A singular lookup promises one entity, so a missing ID means that promise cannot be satisfied. A collection query can validly contain zero members, making an empty array a successful and type-consistent result.

  3. What UI states become necessary once data is asynchronous?

    The UI needs a loading or pending state, a success state with content, an empty state for zero results, and an error state that may offer retry. Controls may also need disabling while a request is pending.

10. What Breaks If This Code Is Removed?

  • Without async, callers never practice waiting for data.
  • Without await, code tries to use a Promise as if it were the result.
  • Without try/catch, rejected operations become unhandled failures.

11. What Was Learned Today

Delayed Promises let a local service reproduce the timing and error-handling shape of a future API.
